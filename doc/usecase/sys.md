# Sys (系统底层) 域设计

> **Sys 域定位**：Sys 是整个 NextPT 系统的基础设施与守护进程大本营。它主要负责底层的定时任务调度（Cron）、分布式缓存封装（Cache）、对象存储接口（S3）以及全局审计日志（SiteAudit）。

## 核心实体 (Domain Entities)
- `CronLog` (定时任务执行日志)


## Usecase 划分及架构设计

> **路由前缀约定**: `无前台业务路由`；运维探针使用根路径 `/healthz` 与 `/readyz`，不经过 `/api` 的鉴权和统一响应封装。
> 
> *注意：Sys 域只提供后端支撑底座，没有针对外网暴露直接访问的 Controller。若需管理定时任务或查看审计日志，全部走面向管理员的 Admin 域。*

### 1. SysCron (系统定时任务引擎)
* **核心职责**：
  * **Start(ctx)**：在服务启动时挂载全局所有的后台守护任务（如清理幽灵节点、对齐种子数据、发放时薪魔力值）。
  * **分布式锁防并发**：提供 `tryAcquireCronLock` 结合 Redis 实现防并发执行。
  * **日志持久化**：提供 `runWrapper` 闭包函数，自动记录任务的执行状态、耗时及 Panic 捕获，写入 `cron_log` 实体表。
  * **日常清理**：每日自动清理过期 7 天的旧日志。
  * **请求认领过期释放**：每 10 分钟调用 CatalogRequestUsecase，批量释放超过认领期限且仍为 `claimed` 的求种/续种请求。求种认领期限为 72 小时，续种为 24 小时；释放使用带状态、认领人和过期时间条件的原子更新，避免与提交动作竞争。

### 2. SysCache (全局分布式缓存策略)
* **核心职责**：
  * **Key 命名空间收敛**：强制使用统一格式管理所有的 Redis Key（如 `KeySiteConfig`, `KeyTorrentSnatched`），杜绝全代码硬编码。
  * **清理器**：提供 `ClearSysCache` 方法，支持按照模式批量清理缓存（如清除某个分类下所有种子的相关缓存）。

### 3. SysStorage (对象存储网关)
* **核心职责**：
  * 封装与底层 MinIO 或 Amazon S3 服务的直接交互逻辑。
  * 提供文件上传、下载预签名 URL、文件删除等统一出口。
  * 为其他域（如 Catalog 域上传种子与字幕）提供不耦合外部云厂商的纯净接口。

### 4. SysHealth (运行状态探针)
* **存活检查**：`GET /healthz` 仅确认 HTTP 服务存活，返回 `204`，不依赖 MySQL 或 Redis。
* **就绪检查**：`GET /readyz` 检查 MySQL 与 Redis，全部可用时返回 `200`；任一不可用时返回 `503`。响应仅包含依赖状态与耗时，不暴露连接错误详情。
* **探针保护**：检查结果在当前进程缓存 3 秒；每项依赖使用 2 秒超时，避免监控请求异常频繁时放大依赖压力。

### 5. SiteMaintenance (站点维护模式)
* **配置**：通过 `site.maintenance_enabled` 和 `site.maintenance_message` 控制。配置更新沿用站点配置缓存失效广播，所有进程即时读取新值。
* **请求范围**：开启后，普通用户的非 Tracker `/api` 请求返回 `503` 与 `Retry-After: 300`；前端收到标准维护响应后跳转至 `/maintenance`。`/healthz`、`/readyz` 和 `/api/tracker/**` 保持可用。
* **Staff 连续操作**：已登录 Staff 不受限制，确保管理后台及其依赖的非 `/admin` API 能完成维护操作。
* **登录限制**：登录与两步验证入口会继续进入 IAM 校验；只有 Staff 可以建立新会话，普通用户得到统一维护响应。
